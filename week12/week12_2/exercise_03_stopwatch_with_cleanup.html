Stopwatch with cleanup

A timer that stops when it should. The interval is started inside an effect and cleared by that effect’s cleanup, so stopping, resetting or leaving the page never leaves a timer ticking.

The task

Build a stopwatch with Start, Stop, and Reset buttons. Use setInterval inside useEffect and clean it up properly to avoid memory leaks.

Lecturer’s Friday study guide — Practice exercise 3

The component

Stopwatch.jsx

function Stopwatch() {
  const [seconds, setSeconds] = useState(0);
  const [running, setRunning] = useState(false);

  useEffect(() => {
    if (!running) return;

    const id = setInterval(() => setSeconds(s => s + 1), 1000);
    return () => clearInterval(id);
  }, [running]);

  return (
    <div>
      <p className="figure" role="timer" aria-live="off">{seconds}s</p>
      <button onClick={() => setRunning(true)} disabled={running}>Start</button>
      <button onClick={() => setRunning(false)} disabled={!running}>Stop</button>
      <button onClick={() => { setRunning(false); setSeconds(0); }}>Reset</button>
    </div>
  );
}

How it works

  • The effect depends on running only. Start sets it to true, so the effect runs and starts an interval. Stop sets it to false, so the cleanup clears that interval.
  • An early return when stopped means no interval is created while the stopwatch is paused.
  • setSeconds(s => s + 1) is the functional form. The interval callback was created once, so a plain seconds + 1 would keep reading the starting value.
  • Without the cleanup, every Start would add another interval and the count would speed up; after unmount the timers would keep firing. That is the leak the slides warn about.
  • Start and Stop are disabled when they would do nothing.
