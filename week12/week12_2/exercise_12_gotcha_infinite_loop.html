Gotcha: infinite loop

An effect that updates the state it depends on never settles. This page runs the buggy effect with a run cap so the browser stays responsive, then runs the fixed version beside it.

The task

If your effect updates state, and that state is in the dependency array, you get an infinite loop. Always think: “does updating this state cause my effect to run again?”

Run BadLoop (capped after 8 runs) and FixedOnce, and compare how many times each effect fires.

The components

BadLoop.jsx — the bug (not run on this page)

function BadLoop() {
  const [count, setCount] = useState(0);

  useEffect(() => {
    setCount(count + 1);   // changes count ...
  }, [count]);             // ... and count is a dependency, so the effect runs again

  return <p>count = {count}</p>;
}

BadLoop.jsx — the same bug with a run cap (what the demo runs)

function BadLoop() {
  const [count, setCount] = useState(0);
  const [stopped, setStopped] = useState(false);
  const runs = useRef(0);

  useEffect(() => {
    runs.current += 1;
    // Safety guard so this demo cannot freeze the page
    if (runs.current > 8) { setStopped(true); return; }
    setCount(count + 1);   // changes count, so the effect runs again
  }, [count]);

  return (
    <div>
      <p className="figure">count = {count}</p>
      <p>Effect runs: {runs.current}</p>
      <p className={stopped ? 'error' : 'loading'} role="status">
        {stopped ? 'Guard stopped it: this loop would never end.' : 'Looping…'}
      </p>
    </div>
  );
}

FixedOnce.jsx — the fix (runs in the demo)

function FixedOnce() {
  const [count, setCount] = useState(0);
  const runs = useRef(0);

  useEffect(() => {
    runs.current += 1;
    setCount(c => c + 1);   // functional update: no need to read count
  }, []);                   // empty array: runs once, after the first render

  return (
    <div>
      <p className="figure">count = {count}</p>
      <p>Effect runs: {runs.current}</p>
      <p role="status">Settled. The effect ran once.</p>
    </div>
  );
}

How it works

  • Why it loops. The effect calls setCount(count + 1), which changes count. count is in the dependency array, so React runs the effect again, which changes count again, and so on. Quiz 7 on the slides asks exactly this and the answer is the [count] version.
  • Why the demo has a cap. The first block above is the real bug, and it is not run here because it never settles. The second block is the same effect plus a runs ref: after 8 updates (on the 9th run) it sets stopped and returns without touching count, which ends the cycle. The counter shows how many times the effect fired.
  • The fix is a functional update with []. setCount(c => c + 1) does not read count from the closure, so the effect no longer depends on it. With an empty array it runs once after the first render.
  • Not every state update in an effect loops. useEffect(() => { setCount(0); }, [count]) converges: once count is 0, React sees the same value (Object.is) and skips the re-render. Slide quiz 7, option D.
  • Other fixes: remove count from the array only when the effect truly does not need it, or do not use an effect at all if the value can be worked out while rendering (see the next exercise).
