localStorage persistence

State that survives a refresh. Read the saved value once when the component mounts, and write it back in an effect whenever it changes. Toggle the theme, then reload the page.

The task

Read from localStorage on mount, write when the value changes, and after a refresh the value is restored: “memory” across page refreshes, no backend.

Lazy initializer: the function form of useState runs only once, at mount, not on every render.

Week 12 Friday slides — Pattern: localStorage Sync

The saved value is stored under the key week12-theme. Open the browser’s developer tools, Application tab, Local Storage, to watch it change.

The component

ThemeToggle.jsx

const STORAGE_KEY = 'week12-theme';

// localStorage can throw (blocked storage, private mode), so guard both calls
function readTheme() {
  try {
    return localStorage.getItem(STORAGE_KEY) === 'dark' ? 'dark' : 'light';
  } catch (err) {
    return 'light';
  }
}

function ThemeToggle() {
  // Read once at mount (lazy initializer form)
  const [theme, setTheme] = useState(() => readTheme());

  // Write whenever theme changes
  useEffect(() => {
    try {
      localStorage.setItem(STORAGE_KEY, theme);
    } catch (err) {
      /* storage is blocked: the choice just will not survive a reload */
    }
  }, [theme]);

  return (
    <div>
      <button onClick={() => setTheme(t => t === 'light' ? 'dark' : 'light')}>
        Current: {theme}. Click to toggle
      </button>
      <div className={'preview ' + theme}>
        <p>This card follows the saved theme.</p>
      </div>
    </div>
  );
}

How it works

  • Two steps, two places. Reading happens in the state initializer, writing happens in an effect. Reading is part of working out the first render, so it belongs there. Writing reaches outside React into the browser’s storage, so it is a side effect and goes in useEffect.
  • The lazy initializer runs once. useState(() => readTheme()) passes a function, which React calls only to compute the starting state on the first render. useState(readTheme()) would read localStorage on every render and throw the result away.
  • The effect depends on [theme]. It runs after the first paint and after each toggle. On mount it writes back the value it just read, which is harmless.
  • Reload to see it work. The state is thrown away on reload, but the initializer reads the saved string and the card comes back in the same theme.
  • Guarded calls. localStorage can throw when storage is blocked, so both calls sit in try/catch. The value read is checked too, so a stray string in storage falls back to light.
  • Different from the slide. The slide stores the key theme and sets data-theme on the whole page. This site’s header toggle already does that in js/main.js under the key theme, so this demo uses its own key and themes only the card, to avoid fighting the header button.
