Practice challenge: GitHub profile

The code challenge again, with the debounce bonus. A GitHubProfile component fetches a user as you type, waits 500 ms after the last keystroke, and cancels anything stale.

The task

Build a component that:

1. Has an <input> for a GitHub username. 2. On Search button click (or debounce 500ms), fetch from https://api.github.com/users/{username}. 3. Display: avatar, name, bio, followers, public_repos. 4. Show a loading indicator while fetching. 5. Show an error message when user is not found (404). 6. BONUS: abort the previous request when username changes.

This version uses the debounce option instead of a Search button.

The component

GitHubProfile.jsx

function GitHubProfile() {
  const [username, setUsername] = useState('muxiddin19');
  const [user, setUser]         = useState(null);
  const [loading, setLoading]   = useState(false);
  const [error, setError]       = useState(null);
  const [keystrokes, setKeystrokes] = useState(0);
  const [requests, setRequests]     = useState(0);

  useEffect(() => {
    const name = username.trim();
    if (!name) { setUser(null); setError(null); setLoading(false); return; }

    const controller = new AbortController();
    setLoading(true);
    setError(null);

    // Debounce: only fetch once typing has stopped for 500 ms
    const timerId = setTimeout(async () => {
      setRequests(n => n + 1);
      try {
        const res = await fetch(`https://api.github.com/users/${encodeURIComponent(name)}`,
                                { signal: controller.signal });
        if (res.status === 404) throw new Error(`User "${name}" not found (404)`);
        if (res.status === 403) throw new Error('GitHub rate limit reached (60 requests an hour). Wait a little and try again.');
        if (!res.ok) throw new Error('Request failed: ' + res.status);
        setUser(await res.json());
      } catch (err) {
        if (err.name === 'AbortError') return;   // a newer request replaced this one
        setUser(null);
        setError(err.message);
      } finally {
        if (!controller.signal.aborted) setLoading(false);
      }
    }, 500);

    // Cleanup: cancel the pending timer AND any request still in flight
    return () => {
      clearTimeout(timerId);
      controller.abort();
    };
  }, [username]);

  return (
    <div>
      <div>
        <label htmlFor="gh-user">GitHub username</label>{' '}
        <input id="gh-user" value={username} placeholder="e.g. torvalds"
               autoComplete="off" spellCheck="false"
               onChange={e => { setKeystrokes(k => k + 1); setUsername(e.target.value); }} />
      </div>
      <p className="muted">Keystrokes: {keystrokes} · requests sent: {requests}</p>

      {loading && <p className="loading" role="status">Loading…</p>}
      {error && <p className="error" role="alert">{error}</p>}
      {user && !loading && (
        <div className="profile">
          <img src={user.avatar_url} alt="" width="96" height="96" />
          <h3>{user.name || user.login}</h3>
          <p>@{user.login} · {user.public_repos} public repos</p>
          <p>{user.bio || <span className="muted">No bio yet.</span>}</p>
        </div>
      )}
    </div>
  );
}

Requirements, one by one

  1. 1. An input for the username. It is controlled by username and starts as muxiddin19, the instructor’s profile from the slides.
  2. 2. Fetch when the username changes. The effect has [username] as its dependency array and calls https://api.github.com/users/{username}. This page uses the real API.
  3. 3. Loading indicator. loading is set as soon as the effect starts, so it also covers the 500 ms debounce wait.
  4. 4. Avatar, name, public repos and bio. Shown together in one card once the data has arrived; the name falls back to the login and the bio to “No bio yet.”
  5. 5. 404 message. A 404 is checked by status and turned into a “not found” message. A 403 gets its own message, because GitHub allows 60 unauthenticated requests an hour per IP.
  6. 6. Bonus, debounce by 500 ms. The fetch lives inside a setTimeout. Each keystroke re-runs the effect, and the cleanup calls clearTimeout, so only the last pause produces a request. Watch the counters: many keystrokes, one request.
  7. Bonus, abort. The same cleanup also calls controller.abort(), which cancels a request that is already in flight. The cancelled fetch throws an AbortError, which the catch ignores, and the finally skips setLoading(false) when the signal was aborted so the newer request keeps the loading state.
