Cleanup with AbortController

Cleanup for a request. The effect hands an AbortController’s signal to the request and aborts it in the cleanup, so changing the username cancels the request that is still in flight.

The task

Cancel the in-flight request if username changes. Ignore the AbortError that a cancelled request throws.

Week 12 Friday slides — Cleanup: AbortController for Fetch

Request log (newest first)

    The API is simulated: every request takes 700 ms, so you can type faster than it answers. Names that start with “nobody”, and an empty box, return 404. The component is the one printed below.

    The component

    UserCard.jsx

    function UserCard({ username }) {
  const [user, setUser]   = useState(null);
  const [error, setError] = useState(null);

  useEffect(() => {
    const controller = new AbortController();
    setError(null);

    async function fetchUser() {
      try {
        const res = await fakeFetch(
          `https://api.github.com/users/${encodeURIComponent(username)}`,
          { signal: controller.signal }   // link to controller
        );
        if (!res.ok) throw new Error('User not found');
        const data = await res.json();
        setUser(data);
      } catch (err) {
        if (err.name === 'AbortError') return;   // ignore cancelled requests
        setError(err.message);
      }
    }
    fetchUser();

    // Cancel the in-flight request if username changes
    return () => controller.abort();
  }, [username]);

  if (error) return <p className="error" role="alert">Error: {error}</p>;
  return (
    <p role="status">{user ? user.login + ' / ' + user.name : 'Loading...'}</p>
  );
}

    Demo.jsx

    function Demo() {
  const [name, setName] = useState('react-learner');

  return (
    <div>
      <label htmlFor="username">GitHub username</label>
      <input id="username" value={name} autoComplete="off"
             onChange={e => setName(e.target.value)} />
      <UserCard username={name} />
    </div>
  );
}

    fakeFetch.js

    // Demo only: stands in for the real GitHub call so that fast typing
// does not use up GitHub's 60 requests an hour. It answers after 700 ms.
function fakeFetch(url, { signal }) {
  const username = decodeURIComponent(url.split('/').pop());
  addLog('started: ' + username);

  return new Promise((resolve, reject) => {
    const timer = setTimeout(() => {
      addLog('finished: ' + username);
      if (!username || username.startsWith('nobody')) {
        resolve({ ok: false, status: 404, json: async () => ({}) });
      } else {
        resolve({ ok: true, status: 200,
                  json: async () => ({ login: username, name: 'Simulated user' }) });
      }
    }, 700);

    signal.addEventListener('abort', () => {
      clearTimeout(timer);
      addLog('aborted: ' + username);
      reject(new DOMException('The request was aborted', 'AbortError'));
    });
  });
}

function addLog(text) {
  const list = document.getElementById('request-log');
  const item = document.createElement('li');
  item.textContent = text;
  list.prepend(item);
  while (list.children.length > 8) list.lastChild.remove();
}

    How it works

    • The signal links the request to the controller. fetch(url, { signal }) listens to it. Calling controller.abort() makes the pending request reject with an AbortError.
    • The cleanup does the aborting. When username changes, React runs the previous effect’s cleanup before the next effect starts, so the old request is cancelled just before the new one begins. Type a few letters and read the log: each earlier request ends with “aborted”, and only the last one reaches “finished”.
    • An aborted request is not an error. The catch block returns early when err.name === 'AbortError', so a cancelled request never calls setError or setUser.
    • The controller is created inside the effect. Each run gets its own, so the cleanup aborts exactly the request that run started.
    • The old card stays until the new answer lands. user is only replaced when a response arrives, which is why the text keeps showing the previous name while the log shows a new request in flight.
    • The fetch is simulated. fakeFetch follows the same contract as fetch (a signal in, an AbortError out, a response with ok and json()), so swapping in the real call changes one word. The real GitHub API allows only 60 unauthenticated requests an hour, which fast typing would use up.
