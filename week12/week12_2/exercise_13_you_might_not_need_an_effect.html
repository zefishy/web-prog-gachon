You might not need an effect

Copying props or state into more state with an effect costs an extra render on every change. Type in either box and compare the two render counters.

The task

What is the best way to compute fullName from the state variables first and last? Compare useEffect(() => setFullName(first + ' ' + last), [first, last]) with const fullName = first + ' ' + last;.

If a value can be calculated from props or state, calculate it during render.

Lecturer’s Friday slides — When NOT to use useEffect; Quiz 8

The components

WithEffect.jsx — an unnecessary effect

function WithEffect({ first, last }) {
  const renders = useRef(0);
  renders.current += 1;                      // demo counter only
  const [fullName, setFullName] = useState('');

  useEffect(() => {
    setFullName(first + ' ' + last);
  }, [first, last]);

  return <p>WithEffect: <strong>{fullName}</strong> (renders: {renders.current})</p>;
}

Derived.jsx — derive it while rendering

function Derived({ first, last }) {
  const renders = useRef(0);
  renders.current += 1;                      // demo counter only
  const fullName = first + ' ' + last;       // worked out while rendering

  return <p>Derived: <strong>{fullName}</strong> (renders: {renders.current})</p>;
}

NameDemo.jsx — the page that feeds both

function NameDemo() {
  const [first, setFirst] = useState('Kim');
  const [last, setLast] = useState('Minho');

  return (
    <div>
      <div>
        <label htmlFor="first-name">First</label>{' '}
        <input id="first-name" value={first} onChange={e => setFirst(e.target.value)} />
      </div>
      <div>
        <label htmlFor="last-name">Last</label>{' '}
        <input id="last-name" value={last} onChange={e => setLast(e.target.value)} />
      </div>
      <WithEffect first={first} last={last} />
      <Derived first={first} last={last} />
    </div>
  );
}

How it works

  • The effect version renders twice per change. Typing changes first or last, so the component renders with the old fullName. After that render the effect runs, calls setFullName, and React renders again. On the first load it also paints an empty name before the effect fills it in.
  • The derived version renders once. fullName is just a constant worked out from the props during the same render, so it is never out of date and needs no extra state.
  • The slides’ flow chart. A response to a user event belongs in an event handler. A value that can be calculated from props or state is computed while rendering. Only syncing with something outside React (network, timers, the DOM) is a job for useEffect. Quiz 8 asks for option D: const fullName = first + ' ' + last;.
  • The render counters are demo-only. Changing a ref during render is not something to do in real components (Strict Mode, which renders twice in development, would double the numbers). Here it just makes the extra render visible.
