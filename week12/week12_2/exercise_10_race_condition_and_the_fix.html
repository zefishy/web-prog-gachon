Race condition and the fix

Without a cleanup, responses can arrive out of order and an old one overwrites the new one. Type “abcdef” fast with the box unticked, then ticked, and compare the result.

The task

WITHOUT abort: responses arrive out of order. WITH abort in the cleanup: only the latest request can finish.

The cleanup of the previous run executes before the next effect starts.

Week 12 Friday slides — Race Condition: Why Abort?

Request log (newest first)

    The API is simulated: requests for shorter names are slower, so a fast typist gets the answers back in the wrong order. Switching the checkbox clears the box so each run starts fresh; wait for the log to settle before you compare.

    The component

    RaceCondition.jsx

    function RaceCondition() {
  const [query, setQuery]   = useState('');
  const [result, setResult] = useState('');
  const [safe, setSafe]     = useState(false);

  useEffect(() => {
    if (!query) return;
    const controller = new AbortController();

    fakeFetch(query, { signal: safe ? controller.signal : undefined })
      .then(res => res.json())
      .then(data => setResult(data.login))
      .catch(err => { if (err.name !== 'AbortError') console.log(err.message); });

    // SAFE mode: cancel the previous request when query changes
    return safe ? () => controller.abort() : undefined;
  }, [query, safe]);

  function toggleSafe(e) {
    setSafe(e.target.checked);
    setQuery('');
    setResult('');
  }

  function typeFast() {
    setQuery('');
    setResult('');
    [...'abcdef'].forEach((_, i) => {
      setTimeout(() => setQuery('abcdef'.slice(0, i + 1)), i * 100);
    });
  }

  const stale = query !== '' && result !== '' && result !== query;

  return (
    <div>
      <label>
        <input type="checkbox" checked={safe} onChange={toggleSafe} />
        {' '}Abort previous request (the fix)
      </label>
      <div>
        <label htmlFor="query">Query</label>
        <input id="query" value={query} autoComplete="off"
               placeholder="type quickly: abcdef"
               onChange={e => setQuery(e.target.value)} />
      </div>
      <button onClick={typeFast}>Type &ldquo;abcdef&rdquo; quickly</button>
      <p>You typed: <b>{query || '-'}</b></p>
      <p aria-live="polite">
        Result shown for: <b>{result || '-'}</b>
        {stale && <span className="error"> (stale!)</span>}
      </p>
    </div>
  );
}

    fakeFetch.js

    // Demo only: a simulated API where SHORTER names are SLOWER
// (1350 ms for one letter down to 200 ms for six), so responses
// arrive out of order when you type quickly.
function fakeFetch(query, { signal } = {}) {
  const delay = Math.max(200, 1600 - query.length * 250);
  addLog('sent "' + query + '"');

  return new Promise((resolve, reject) => {
    const timer = setTimeout(() => {
      addLog('response for "' + query + '" arrived after ' + delay + ' ms');
      resolve({ json: async () => ({ login: query }) });
    }, delay);

    signal?.addEventListener('abort', () => {
      clearTimeout(timer);
      addLog('aborted "' + query + '"');
      reject(new DOMException('The request was aborted', 'AbortError'));
    });
  });
}

function addLog(text) {
  const list = document.getElementById('request-log');
  const item = document.createElement('li');
  item.textContent = text;
  list.prepend(item);
  while (list.children.length > 8) list.lastChild.remove();
}

    How it works

    • The race. Each keystroke starts a request, but the network does not answer in the order the requests were sent. Here a one-letter query takes 1350 ms and a six-letter query 200 ms, so “a” comes back last and its answer replaces the one for “abcdef”. The box says abcdef and the result says a, marked stale.
    • The fix is the cleanup from the previous exercise. In safe mode the effect passes controller.signal to the request and returns () => controller.abort(). Before the effect runs for “abcdef”, the cleanup for “abcde” has already cancelled that request, and so on back to “a”. Only the latest request can reach setResult.
    • Why safe is in the dependency array. The effect reads it, so the lint rule wants it listed. Ticking the box re-runs the effect with the other behaviour.
    • The unsafe branch returns undefined. With no signal and no cleanup the old requests keep running and still call setResult, which is the bug being shown.
    • Even the fixed version lags. Type and delete a character and the result still shows the old text for a moment, flagged stale, until the newest answer arrives. The fix guarantees the result cannot end up on an old query, not that it is always current.
    • The “Type abcdef quickly” button is an addition so the race can be reproduced exactly: it types one letter every 100 ms.
    • The other way to ignore an old response is a flag set in the cleanup (let ignore = false; return () => { ignore = true; }), which also works for APIs that cannot be aborted. The slide’s quiz answer says “aborts (or ignores)”.
