Fetch a user from an API

The most common job for useEffect: load data once the component is on screen, then store it in state. Three pieces of state cover the three outcomes: loading, an error, or the user.

The task

Use https://jsonplaceholder.typicode.com/users/1 to fetch a user and display their name and email. Show “Loading…” while fetching and handle errors.

Lecturer’s Friday study guide — Practice exercise 2

The component

UserProfile.jsx

function UserProfile() {
  const [user, setUser]       = useState(null);
  const [loading, setLoading] = useState(true);
  const [error, setError]     = useState(null);

  useEffect(() => {
    async function fetchUser() {
      try {
        const res  = await fetch('https://jsonplaceholder.typicode.com/users/1');
        if (!res.ok) throw new Error('Failed to fetch');
        const data = await res.json();
        setUser(data);
      } catch (err) {
        setError(err.message);
      } finally {
        setLoading(false);
      }
    }
    fetchUser();
  }, []);

  if (loading) return <p className="loading" role="status">Loading…</p>;
  if (error)   return <p className="error" role="alert">Error: {error}</p>;

  return (
    <div>
      <h3>{user.name}</h3>
      <p>{user.email}</p>
    </div>
  );
}

How it works

  • The three-state pattern from the slides: loading starts true, and exactly one of user or error is set when the request settles.
  • The async function is defined inside the effect and called straight away. The effect callback itself is not async, because it must return nothing or a cleanup, not a Promise.
  • finally clears the loading flag on both success and failure, so it is written once.
  • [] means once, after the first render. The user id never changes here, so there is nothing to re-fetch on.
  • fetch only rejects on network failure, which is why !res.ok is checked by hand to turn a 404 or 500 into an error.
