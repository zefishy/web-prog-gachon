GitHub user lookup

The Friday code challenge. A search box that fetches a GitHub profile when Search is pressed, with a loading state, a 404 message, and the bonus: an AbortController that cancels the previous request.

The task

Build a component that:

1. Has an <input> for a GitHub username. 2. On Search button click (or debounce 500ms), fetch from https://api.github.com/users/{username}. 3. Display: avatar, name, bio, followers, public_repos. 4. Show a loading indicator while fetching. 5. Show an error message when user is not found (404). 6. BONUS: abort the previous request when username changes.

Tip: search “muxiddin19” to test with the instructor’s profile!

The component

GitHubUserLookup.jsx

function GitHubUserLookup() {
  const [input, setInput]       = useState('');
  const [username, setUsername] = useState('');
  const [user, setUser]         = useState(null);
  const [loading, setLoading]   = useState(false);
  const [error, setError]       = useState(null);

  useEffect(() => {
    if (!username) return;
    const controller = new AbortController();
    setLoading(true); setError(null); setUser(null);

    fetch(`https://api.github.com/users/${encodeURIComponent(username)}`,
          { signal: controller.signal })
      .then(res => {
        if (res.status === 404) throw new Error('User not found (404)');
        if (!res.ok) throw new Error('Request failed: ' + res.status);
        return res.json();
      })
      .then(data => { setUser(data); setLoading(false); })
      .catch(err => {
        if (err.name === 'AbortError') return;
        setError(err.message); setLoading(false);
      });

    return () => controller.abort();
  }, [username]);

  function search(e) {
    e.preventDefault();
    setUsername(input.trim());
  }

  return (
    <div>
      <form onSubmit={search}>
        <input value={input} placeholder="GitHub username" aria-label="GitHub username"
               onChange={e => setInput(e.target.value)} />
        <button>Search</button>
      </form>

      {loading && <p className="loading" role="status">Loading…</p>}
      {error && <p className="error" role="alert">{error}</p>}
      {user && (
        <div className="profile">
          <img src={user.avatar_url} alt="" width="72" height="72" />
          <h3>{user.name || user.login}</h3>
          <p>{user.bio || <span className="muted">No bio.</span>}</p>
          <p>{user.followers} followers · {user.public_repos} public repos</p>
          <a href={user.html_url}>{user.html_url}</a>
        </div>
      )}
    </div>
  );
}

How it works

  • Two strings, on purpose. input follows every keystroke; username only changes when Search is pressed. The effect depends on username, so typing alone never fetches.
  • Loading, error and user are reset at the start of each search, so an old profile never sits under a new error.
  • 404 is checked by status to give the “not found” message the task asks for; anything else that is not OK gets a general error.
  • Bonus: the cleanup aborts. A new search runs the previous effect’s cleanup first, which calls controller.abort(); the cancelled request then throws an AbortError, which is ignored.
  • The input sits in a <form>, so Enter searches as well as the button. GitHub’s API allows 60 unauthenticated requests an hour per IP.
