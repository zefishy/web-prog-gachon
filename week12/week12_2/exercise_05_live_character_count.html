Live character count

The practice task from the end of the Friday slides: a live character count on an input, kept in sync with useEffect. It works, and it is also a good example of an effect the slides say you might not need.

The task

Practice: add a live character count to any input using useEffect.

Week 12 Friday slides — Next Session & Resources, Practice

The component

CharacterCount.jsx

const LIMIT = 140;

function CharacterCount() {
  const [text, setText]   = useState('');
  const [count, setCount] = useState(0);

  useEffect(() => {
    setCount(text.length);
  }, [text]);

  const left = LIMIT - count;

  return (
    <div>
      <label htmlFor="cc-text">Your message</label>
      <input id="cc-text" value={text} onChange={e => setText(e.target.value)}
             placeholder="Type here…" style={{ width: '100%' }} />
      <p aria-live="polite">
        <span className="figure">{count}</span> characters ·{' '}
        <span className={left < 0 ? 'error' : 'muted'}>{left} left of {LIMIT}</span>
      </p>
    </div>
  );
}

The version without an effect

The slides’ “When NOT to use useEffect” flowchart asks: can it be calculated from props or state? The count can, so the effect and the second piece of state could both go:

Derived instead

function CharacterCount() {
  const [text, setText] = useState('');
  const count = text.length;
  // ...same JSX
}

How it works

  • The task asks for useEffect, so the page uses it: whenever text changes, the effect copies its length into count.
  • The cost is one extra render per keystroke. React renders with the new text and the old count, runs the effect, then renders again with the new count.
  • Deriving it is the better habit. Quiz 8 in the Friday slides makes the same point about fullName: compute it during render, with no state and no effect.
  • The remaining count turns red past 140 characters, the way a post box would warn you.
