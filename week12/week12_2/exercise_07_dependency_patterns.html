The three dependency patterns

Three effects in three child components, one parent. Change val, or only re-render, and compare which effects log.

The task

Compare which effects log when you change val and when you only re-render.

useEffect(fn) — after every render (avoid, usually wrong). useEffect(fn, []) — once, after the first render. useEffect(fn, [a, b]) — after the first render, and whenever a or b changes.

Week 12 Friday slides — useEffect syntax and the dependency array

Three lines appear on load. Then try each button once and read only the new lines.

The component

DependencyPatterns.jsx

// The log lives outside React state on purpose: see the notes.
let lines = [];
const listeners = new Set();
function log(...args) {
  lines = [...lines, args.join(' ')];
  listeners.forEach(fn => fn(lines));
}
function clearLog() {
  lines = [];
  listeners.forEach(fn => fn(lines));
}

function LogPanel() {
  const [shown, setShown] = useState(lines);
  useEffect(() => {
    listeners.add(setShown);
    setShown(lines);
    return () => { listeners.delete(setShown); };
  }, []);

  return (
    <div>
      <h3>Effect log</h3>
      <div role="log" aria-label="Effect log">
        {shown.length
          ? <ul>{shown.map((line, i) => <li key={i}>{line}</li>)}</ul>
          : <p className="muted">Nothing logged yet.</p>}
      </div>
      <button onClick={clearLog}>Clear log</button>
    </div>
  );
}

function RunsOnce() {
  useEffect(() => { log('[]     -> ran once after mount'); }, []);
  return <p><code>[]</code> : once after mount</p>;
}

function RunsOnChange({ val }) {
  useEffect(() => { log('[val]  -> ran, val =', val); }, [val]);
  return <p><code>[val]</code> : when val changes</p>;
}

function RunsEveryRender() {
  // No dependency array: usually a bug
  useEffect(() => { log('(none) -> ran after EVERY render'); });
  return <p><code>(none)</code> : after every render</p>;
}

function DependencyPatterns() {
  const [val, setVal]   = useState(0);
  const [tick, setTick] = useState(0);
  return (
    <div>
      <button onClick={() => setVal(v => v + 1)}>val++ (changes val)</button>
      <button onClick={() => setTick(t => t + 1)}>re-render (val unchanged)</button>
      <p>val = {val}, extra renders = {tick}</p>
      <RunsOnce />
      <RunsOnChange val={val} />
      <RunsEveryRender />
      <LogPanel />
    </div>
  );
}

How it works

  • val++ logs two lines: [val] because its dependency changed, and (none) because the parent re-rendered. [] stays silent.
  • “re-render” logs one line. tick changes the parent’s state, every child renders again, but val is the same number, so [val] is skipped. Only the effect with no array runs.
  • The array compares values with Object.is, one entry at a time. That is why a number or string works as a dependency and a new {} or [] created during render would trigger the effect every time.
  • The log is not React state in the parent. If it were, logging from the no-array effect would change the parent’s state, re-render all three children, and log again, forever. Here LogPanel subscribes to a small list outside React, in an effect with its own cleanup, so only the panel re-renders. This is the infinite-loop trap from a later exercise, avoided by design.
  • No array is almost never what you want. It is in the demo to show what the other two save you from.
