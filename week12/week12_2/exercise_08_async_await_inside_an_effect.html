async/await inside an effect

The async function is defined inside the effect and called straight away, because the effect callback itself must not be async.

The task

You cannot make the useEffect callback itself async: it would return a Promise, but React expects nothing or a cleanup function. Define an async function inside the effect and call it.

Fetch https://api.github.com/users/muxiddin19 with await, show Loading while it runs, and show either the user or the error.

Week 12 Friday slides — async/await inside useEffect

This calls the real GitHub API once on load, and once more for each press of “Fetch again”. GitHub allows 60 unauthenticated requests an hour per IP, so if it answers 403 the page shows that as an error.

The component

AsyncEffect.jsx

function AsyncEffect() {
  const [user, setUser]       = useState(null);
  const [error, setError]     = useState(null);
  const [loading, setLoading] = useState(true);

  // CORRECT: define the async function inside and call it
  useEffect(() => {
    async function fetchData() {
      try {
        const res = await fetch('https://api.github.com/users/muxiddin19');
        if (!res.ok) throw new Error('GitHub responded ' + res.status);
        const data = await res.json();
        setUser(data);
      } catch (err) {
        setError(err.message);
      } finally {
        setLoading(false);
      }
    }
    fetchData();
    // No return needed here unless we have cleanup
  }, []);

  if (loading) return <p className="loading" role="status">Loading...</p>;
  if (error)   return <p className="error" role="alert">Error: {error}</p>;
  return <p><strong>{user.login}</strong>: {user.name || '(no name set)'}</p>;
}

function Demo() {
  const [run, setRun] = useState(1);
  return (
    <div>
      <button onClick={() => setRun(r => r + 1)}>Fetch again</button>
      <AsyncEffect key={run} />
    </div>
  );
}

The wrong version (not run on this page)

// WRONG: an async callback returns a Promise, but useEffect
// expects undefined or a cleanup function
useEffect(async () => {
  const res  = await fetch('https://api.github.com/users/muxiddin19');
  const data = await res.json();
  setUser(data);
}, []);

How it works

  • Why not useEffect(async () => ...)? An async function always returns a Promise. React treats whatever the effect returns as the cleanup function, so it would try to call a Promise on unmount. React 18 also logs a warning about it in development builds.
  • The fix is a named async function inside the effect, called on the next line. The effect callback stays ordinary and returns nothing, so it could still return a cleanup.
  • try / catch / finally carries the three states: setUser on success, setError on failure, and setLoading(false) either way. fetch only rejects on network failure, so the res.ok check turns a 403 or 404 into an error as well.
  • Fetch again remounts the component by changing its key. The new instance starts with loading true and runs its [] effect again. Demo and the button are mine; AsyncEffect follows the slides.
  • No cleanup yet. If the component unmounts before the response arrives, the request still finishes. Exercise 9 adds an AbortController.
