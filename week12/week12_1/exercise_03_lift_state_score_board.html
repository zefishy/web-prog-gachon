Lift state between two counters

Two children, one owner. The scores live in the parent ScoreBoard, so it can show the total; each PlayerScore only reads its score and calls back up to change it.

The task

Create a parent ScoreBoard with two PlayerScore children. Each player has increment/decrement buttons. The parent shows the total score of both players combined.

Lecturer’s Monday study guide — Practice exercise 3

The components

ScoreBoard.jsx

function PlayerScore({ name, score, onIncrement, onDecrement }) {
  return (
    <div>
      <h3>{name}: <span className="figure">{score}</span></h3>
      <button onClick={onDecrement} aria-label={'Decrease ' + name}>−</button>
      <button onClick={onIncrement} aria-label={'Increase ' + name}>+</button>
    </div>
  );
}

function ScoreBoard() {
  const [p1, setP1] = useState(0);
  const [p2, setP2] = useState(0);
  return (
    <div>
      <PlayerScore name="Player 1" score={p1}
        onIncrement={() => setP1(p => p + 1)}
        onDecrement={() => setP1(p => p - 1)} />
      <PlayerScore name="Player 2" score={p2}
        onIncrement={() => setP2(p => p + 1)}
        onDecrement={() => setP2(p => p - 1)} />
      <h2>Total: {p1 + p2}</h2>
    </div>
  );
}

How it works

  • Data flows down. score reaches each child as a prop. The child never stores its own copy.
  • Events flow up. onIncrement and onDecrement are callbacks from the parent; the child calls them and the parent’s setter does the work.
  • The total is not state. p1 + p2 is computed during render, so it cannot drift out of sync with the two scores.
  • If each PlayerScore kept its own useState, the parent would have no way to read the two values to add them. That is the reason to lift.
