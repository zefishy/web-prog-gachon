Add & remove items from a list

Array state, updated the immutable way. Adding spreads the old array into a new one; removing filters into a new one. The original array is never pushed to or spliced.

The task

Build a component with a text input and “Add” button. Items typed in the input are added to an array stored in state. Each item has a “✕” button that removes it from the list.

The component

TaskList.jsx

function TaskList() {
  const [tasks, setTasks] = useState([]);
  const [input, setInput] = useState('');

  function addTask() {
    if (!input.trim()) return;
    setTasks(prev => [...prev, { id: Date.now(), text: input.trim() }]);
    setInput('');
  }

  function removeTask(id) {
    setTasks(prev => prev.filter(t => t.id !== id));
  }

  return (
    <div>
      <input value={input} onChange={e => setInput(e.target.value)}
             onKeyDown={e => e.key === 'Enter' && addTask()}
             placeholder="New task" aria-label="New task" />
      <button onClick={addTask}>Add</button>
      <ul>
        {tasks.map(task => (
          <li key={task.id}>
            {task.text}
            <button onClick={() => removeTask(task.id)} aria-label={'Remove ' + task.text}>✕</button>
          </li>
        ))}
      </ul>
      {tasks.length === 0 && <p className="muted">No tasks yet.</p>}
    </div>
  );
}

How it works

  • Two pieces of state. tasks is the list; input is the text box. Each has its own setter, as the slides recommend for independent values.
  • Add: [...prev, item]. A new array with the old items plus one. tasks.push() would keep the same reference, and React would skip the re-render.
  • Remove: prev.filter(...). filter always returns a new array, so it is immutable by design.
  • Keys come from the data. Each task gets id: Date.now(), so removing one item does not make React confuse the rows after it.
  • Pressing Enter also adds a task, and each ✕ button is labelled with the task it removes.
