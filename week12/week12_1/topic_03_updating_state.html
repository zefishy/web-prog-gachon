Updating state

Three rules cover almost every bug: do not mutate, copy before you change, and use the callback form when the new value depends on the old one.

React compares the new value with the old one by reference. Mutate an object or push into an array and the reference is unchanged, so React skips the render and the screen lies. Spreading creates a new reference, which is exactly the signal React waits for.

The panels below take the rules in turn: objects, an object held in a form, arrays (add, toggle, remove), and the callback form.

// ❌ mutates the object — same reference, no re-render
user.age = user.age + 1; setUser(user);

// ✅ copy, then override
setUser({ ...user, age: user.age + 1 });

// ❌ mutates the array
items.push('new'); setItems(items);

// ✅ new array
setItems([...items, 'new']);

// callback form: both reads see the same stale value
setCount(count + 1); setCount(count + 1);   // +1
setCount(c => c + 1); setCount(c => c + 1); // +2
