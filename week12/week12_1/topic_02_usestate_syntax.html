useState syntax

One call returns a pair: the current value and the function that replaces it. The argument is the initial value, used only on the first render.

The pattern is always the same — const [value, setValue] = useState(initialValue) — and the initial value can be a number, string, boolean, array or object. Pass a function instead and React calls it once, lazily, which is how you avoid doing expensive work on every render.

const [count, setCount] = useState(0);          // number
const [text, setText]   = useState('');         // string
const [open, setOpen]   = useState(false);      // boolean
const [items, setItems] = useState([]);         // array
const [user, setUser]   = useState({ name: 'Ryan' });  // object

const [rows] = useState(() => buildRows());    // lazy: runs once

Rules of Hooks

React never learns the names you chose. It matches each useState call to its state slot by the order the calls run in, so that order has to be identical on every render. The Rules of Hooks are that fact written down:

  • Call hooks at the top level of the component — never inside a loop, an if or a nested function.
  • Call hooks only from React function components, or from a custom hook whose name starts with use.
  • Call them in the same order every render, so the first call always finds the first slot.
  • The official eslint-plugin-react-hooks flags a violation as you type; with no build step here, the rule is on you.
// ❌ the call runs on some renders only, so the later slots shift
if (open) { const [draft, setDraft] = useState(''); }

// ❌ one hook per item: the number of calls changes with the array
items.forEach((item) => { const [on, setOn] = useState(false); });

// ✅ top level, same order on every render
const [open, setOpen]   = useState(false);
const [draft, setDraft] = useState('');
const [items, setItems] = useState([]);

The lazy line exists only to show the factory form: it runs on the first render and never again, even as the counters change.
