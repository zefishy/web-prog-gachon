Interactive Colour Palette

Exercise 5 puts the week's pieces together: state in an array, click and double-click events, DOM building, form input, and localStorage. The result is a palette that belongs to you — shape it, export it as an image, reload the page, and it is still there. It starts with this library's shelf greens, but it will not keep them long.

Week 5 · Exercise 5, and the lecturer's week 5 template (interactive colour palette.html).

The interactions

  • Click a colour box to expand it and reveal its hex code.
  • Double-click a colour box to remove it from the palette — or open it and use the × button, which does the same job from the keyboard.
  • Add colour — type a hex code (e.g. #ff5733) and press Add Colour to create a new box.
  • Export PNG — downloads the current palette as an image file.

How localStorage works here

  • Every time you add or remove a colour, the current list of hex codes is saved with localStorage.setItem().
  • When the page reloads, the saved list is read back with localStorage.getItem() and the boxes are restored automatically.
  • That means your palette persists across page reloads — add a colour, refresh, and it is still there. Try it.

The palette lives in your browser's storage for this site only — it never leaves your machine, and clearing the site's browsing data resets it to the five shelf greens.

The pieces it practices

    1

    State as an array

    The palette is one array of hex strings. Rendering means rebuilding the boxes from that array — the array is the truth, the boxes are its picture.

    2

    Events on elements that did not exist at load

    Boxes are created in JavaScript, so their click and double-click handlers are attached the moment each one is built.

    3

    Input validation

    The add field checks the six-digit hex pattern before touching the array — #ff5733 in, an error message for everything else.

    4

    localStorage

    Every change is written straight back, so the next page load starts where this one ended.
