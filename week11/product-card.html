Week 11: React props

Week 11 — ProductCard

The in-class code challenge: one component, four props, and a card that changes completely when the props change. Nothing inside ProductCard knows what product it is showing — the parent passes name, price, rating and inStock in, and the component renders whatever it is given. That is the whole idea of props.

The code challenge

From the React Props slides’ Code Challenge. Build a ProductCard component that accepts name (string), price (number, KRW), rating (0–5) and inStock (boolean) as props, and renders a product card from them. Render it with different props more than once.

React Props slides — Code Challenge

The required call

<ProductCard
  name="Wireless Earbuds"
  price={89000}
  rating={4.5}
  inStock={true}
/>

The card, live

Three instances of the same component below, from the same array of plain objects. Only the props differ — there is no per-product markup anywhere. The third product has inStock: false, which is what turns its badge into “Out of Stock”.

The four props

Every prop is a name and a value. In JSX the value sits between braces when it is JavaScript — price={89000} — and in quotes when it is a string — name="Wireless Earbuds". Both arrive as the same kind of thing on the other side: an entry on the props object.

Prop Type Renders as
name string The product name, in the card’s heading.
price number, KRW 89,000 KRW — grouped with toLocaleString, not built by hand.
rating number, 0–5 4.5 / 5 stars plus a row of star glyphs.
inStock boolean In Stock, or Out of Stock when false.

The component

This is the exact code running above, transcribed out of the page. The only unusual line is the badge: a ternary picks the label, and the class name is built with a string concatenation so the “out” variant can be styled differently.

ProductCard.js

function Stars({ rating }) {
  const full = Math.floor(rating);
  const half = rating - full >= 0.5;
  const empty = 5 - full - (half ? 1 : 0);
  return (
    <span className="product-card__stars" aria-hidden="true">
      {'★'.repeat(full)}{half ? '½' : ''}{'☆'.repeat(empty)}
    </span>
  );
}

function ProductCard({ name, price, rating, inStock }) {
  return (
    <article className="product-card">
      <h3 className="product-card__name">{name}</h3>
      <p className="product-card__price">
        {price.toLocaleString('ko-KR')} KRW
      </p>
      <p className="product-card__rating">
        <Stars rating={rating} />
        <span>{rating} / 5 stars</span>
      </p>
      <p className={'product-card__stock' + (inStock ? '' : ' is-out')}>
        {inStock ? 'In Stock' : 'Out of Stock'}
      </p>
    </article>
  );
}

const products = [
  { name: 'Wireless Earbuds',    price: 89000,  rating: 4.5, inStock: true  },
  { name: 'Mechanical Keyboard', price: 129000, rating: 4.8, inStock: true  },
  { name: 'USB-C Hub',           price: 45000,  rating: 3.5, inStock: false },
];

ReactDOM.createRoot(document.getElementById('product-card-demo')).render(
  products.map((product) => (
    <ProductCard key={product.name} {...product} />
  ))
);

What the code is actually doing

  • JSX is not HTML. <article> inside a .js file is a syntax error until something rewrites it into React.createElement('article', …). The submitted project does that at build time with Babel; this page loads Babel in the browser to do it live, which is why it is slower to first paint and only suitable for a demo.
  • Props move one way. A component receives props and renders them; it never writes back to them. If the parent re-renders with a different rating, the card updates. If the card wants to change something, it asks the parent to re-render.
  • Braces mean JavaScript. price={89000} passes the number 89000, so toLocaleString() and arithmetic both work. price="89000" passes a string, and price + 1 quietly becomes "890001".
  • Conditional rendering returns something renderable. The badge returns a string, a missing field returns null, and false renders nothing. All three are fine; undefined is too, which is why a forgotten prop shows up as a blank card rather than a crash.
  • The key is not a prop. key is used by React to match the list before and after a re-render, and it never reaches ProductCard. Use a stable value from the data — the name here, or better an id — never the array index.
