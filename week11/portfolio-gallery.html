The four components

The slides suggest giving each component one job: sketch the screen, draw a box around each part, and make each box a component. Below is the actual TypeScript source from the repository, copied without changes.

Projects — the parent component

Projects is the only component with state. It stores the selected filter as a string with useState. On every render it works out two lists from the project data: the filter buttons (one per technology, with duplicates removed by a Set) and the projects that match the current filter. FilterBar is the only component that changes the filter, and ProjectList only displays the result. The project data is stored here too, so adding a fourth project just means adding another object to the array.

src/components/Projects.tsx

import { useState } from "react";
import FadeIn from "./FadeIn";
import ProjectCard from "./ProjectCard";
import ProjectList from "./ProjectList";
import FilterBar from "./FilterBar";

interface Project {
  title: string;
  description: string;
  tech: string[];
  liveUrl?: string;
  repoUrl?: string;
  image?: string;
}

const projects: Project[] = [
  {
    title: "E-Commerce Web Application",
    description:
      "Building a E-Commerce website for a Singapore-based Agricutural Company - My Year 1 Final Project for Nanyang Polytechnic",
    tech: ["Python", "Flask", "Supabase", "Stripe"],
    liveUrl: "#",
    repoUrl: "https://github.com/zefishy/wdp",
    image: "/e-commerce-app.png",
  },
  {
    title: "Discord Bot with DiscordJS",
    description:
      "I developed a discord bot with DiscordJS to handle simple administrative functions",
    tech: ["JavaScript", "DiscordJS"],
    repoUrl: "https://github.com/zefishy/discord-bot",
    image: "/discord-bot.png",
  },
  {
    title: "Web Programming Library",
    description:
      "A static HTML/CSS/JS coursework library with per-week exercise folders, themed spines, and accessibility-focused design.",
    tech: ["HTML", "CSS", "JavaScript"],
    liveUrl: "https://zefishy.github.io/web-prog-gachon/",
    repoUrl: "https://github.com/zefishy/web-prog-gachon",
    image: "/web-prog-library.png",
  },
];

export default function ProjectsSection() {
  const [activeFilter, setActiveFilter] = useState<string>("All");

  const techs = [
    "All",
    ...Array.from(
      new Set(projects.flatMap((p) => p.tech))
    ).sort(),
  ];

  const filteredProjects = projects.filter((p) =>
    activeFilter === "All" ? true : p.tech.includes(activeFilter)
  );

  return (
    <section id="projects" className="section-container">
      <FadeIn>
        <p className="text-primary font-mono text-sm mb-2 tracking-wider uppercase">
          Projects
        </p>
        <h2 className="section-heading">My Projects</h2>
        <p className="section-subheading">
          Some Personal/Professional Projects I've Built Over the Years.
        </p>
      </FadeIn>

      <FilterBar
        techs={techs}
        activeFilter={activeFilter}
        onFilter={setActiveFilter}
      />

      <ProjectList projects={filteredProjects} />
    </section>
  );
}

FilterBar — the filter buttons

FilterBar gets three props: the list of technologies (with All already at the front), the selected one, and a function to call when a button is clicked. It has no state of its own. It decides which button looks active by comparing each technology with activeFilter.

src/components/FilterBar.tsx

interface FilterBarProps {
  techs: string[];
  activeFilter: string;
  onFilter: (filter: string) => void;
}

export default function FilterBar({
  techs,
  activeFilter,
  onFilter,
}: FilterBarProps) {
  return (
    <div className="flex flex-wrap gap-2 mb-6">
      {techs.map((tech) => (
        <button
          key={tech}
          onClick={() => onFilter(tech)}
          className={`px-4 py-2 rounded-full border text-sm transition-colors ${
            activeFilter === tech
              ? "bg-primary text-primary-foreground"
              : "border-border text-muted-foreground hover:bg-secondary"
          }`}
        >
          {tech}
        </button>
      ))}
    </div>
  );
}

ProjectList — one card per project

ProjectList maps over the projects and renders a card for each one. I used each project’s title as the key instead of the array index, so React can tell which card is which when the filter changes. Each card is wrapped in FadeIn, which fades the cards in one after another.

src/components/ProjectList.tsx

import FadeIn from "./FadeIn";
import ProjectCard from "./ProjectCard";

interface ProjectListProps {
  projects: Project[];
}

interface Project {
  title: string;
  description: string;
  tech: string[];
  liveUrl?: string;
  repoUrl?: string;
  image?: string;
}

export default function ProjectList({ projects }: ProjectListProps) {
  return (
    <div className="grid grid-cols-1 md:grid-cols-2 gap-6">
      {projects.map((project, i) => (
        <FadeIn key={project.title} delay={i * 0.1}>
          <ProjectCard
            title={project.title}
            description={project.description}
            tech={project.tech}
            liveUrl={project.liveUrl}
            repoUrl={project.repoUrl}
            image={project.image}
          />
        </FadeIn>
      ))}
    </div>
  );
}

ProjectCard — one project

ProjectCard shows whatever project it is given through props. The image and both links are optional, so a project with no demo link or screenshot still shows up as a normal card.

src/components/ProjectCard.tsx

import { ExternalLink, Github } from "lucide-react";
import { Badge } from "./ui/badge";

interface ProjectCardProps {
  title: string;
  description: string;
  tech: string[];
  liveUrl?: string;
  repoUrl?: string;
  image?: string;
}

export default function ProjectCard({
  title,
  description,
  tech,
  liveUrl,
  repoUrl,
  image,
}: ProjectCardProps) {
  return (
    <div className="glass-card h-full flex flex-col">
      {image && (
        <div className="rounded-lg overflow-hidden mb-4 bg-secondary/50 aspect-video">
          <img src={image} alt={title} className="w-full h-full object-cover" />
        </div>
      )}
      <h3 className="font-semibold text-lg mb-2">{title}</h3>
      <p className="text-muted-foreground text-sm mb-4 flex-1">{description}</p>
      <div className="flex flex-wrap gap-2 mb-4">
        {tech.map((t) => (
          <Badge key={t} variant="secondary" className="text-xs">
            {t}
          </Badge>
        ))}
      </div>
      <div className="flex gap-3">
        {liveUrl && (
          <a
            href={liveUrl}
            target="_blank"
            rel="noopener noreferrer"
            className="inline-flex items-center gap-1.5 text-sm text-primary hover:underline"
          >
            <ExternalLink className="w-4 h-4" /> Live Demo
          </a>
        )}
        {repoUrl && (
          <a
            href={repoUrl}
            target="_blank"
            rel="noopener noreferrer"
            className="inline-flex items-center gap-1.5 text-sm text-muted-foreground hover:text-foreground transition-colors"
          >
            <Github className="w-4 h-4" /> Source Code
          </a>
        )}
      </div>
    </div>
  );
}

How the filtering works

  • The state is in the parent. Projects stores a single string: the selected technology. The slides don’t cover useState until next week, but filtering needs one piece of state, so the gallery uses that one hook.
  • The lists are recalculated on each render. The visible projects and the filter buttons both come from projects and activeFilter every time the component renders. I don’t store a second, filtered array, so what’s on screen always matches the selected filter.
  • The child calls a function from the parent. When a button is clicked, FilterBar calls onFilter(tech), which is the state setter passed down from Projects. React then re-renders Projects, and both children get new props. The child components never change the data themselves.
  • Keys keep track of the cards. When the filter hides some cards, React uses each card’s title key to remove the right ones. With index keys, the remaining cards would be renumbered and React could reuse the wrong DOM elements.
  • Why four components. All of this could go in one long function, but then the filter logic, buttons, list and card markup would be mixed together. Splitting it up means I can read or change each part on its own.
