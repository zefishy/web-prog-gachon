Accessibility audit walkthrough

Do the Lighthouse accessibility homework yourself, step by step. Work through the checklist, learn to recognise the seven failures that show up most, and check any colour pair with the contrast calculator.

1. The homework checklist

The lecturer’s homework is five steps (source: Accessibility slides — Summary & Homework). Tick each one off as you go. Ticks are not saved, they only track this visit.

0 of 5 steps done

The slides ask for 100 on the initial run. If your page already scores 100 there is nothing failing to fix. To practise, run the same steps on the sign-up form before the fixes.

2. The common failing audits

These seven account for most of the red items in an accessibility report. Each card names the Lighthouse audit, shows a failing snippet and the fixed version. Pick any three that your own report flags.

Missing alt text

Lighthouse audit: image-alt

Every <img> needs an alt attribute. Describe the purpose; use alt="" when the image is decorative.

× Failing

<img src="team.jpg">

✓ Fixed

<img src="team.jpg" alt="Team 16 at the project demo">

Low colour contrast

Lighthouse audit: color-contrast

Body text needs 4.5:1 against its background (3:1 for large text). Check the pair in the calculator below.

× Failing

.note { color: #999999; background: #ffffff; }  /* 2.84:1 */

✓ Fixed

.note { color: #595959; background: #ffffff; }  /* 7.00:1 */

Form input without a label

Lighthouse audit: label

A placeholder is not a label. Connect a visible <label> to the input with for and id.

× Failing

<input type="email" placeholder="Email">

✓ Fixed

<label for="email">Email</label>
<input type="email" id="email" name="email">

Missing html lang

Lighthouse audit: html-has-lang

Screen readers pick the pronunciation from the lang attribute on the root element.

× Failing

<html>

✓ Fixed

<html lang="en">

Link without a name

Lighthouse audit: link-name

An icon-only link has no text, so a screen reader announces just "link". Give it an accessible name.

× Failing

<a href="https://github.com/zefishy"><svg>...</svg></a>

✓ Fixed

<a href="https://github.com/zefishy" aria-label="Ryan on GitHub"><svg aria-hidden="true">...</svg></a>

Heading order skips a level

Lighthouse audit: heading-order

Headings go down one level at a time. Pick the level for the outline, then size it with CSS.

× Failing

<h1>Forum</h1>
<h4>Latest posts</h4>

✓ Fixed

<h1>Forum</h1>
<h2>Latest posts</h2>

Label not in the accessible name

Lighthouse audit: label-content-name-mismatch

Voice-control users say what they see. If aria-label replaces the visible text, it must still contain that text.

× Failing

<button aria-label="Send">Submit form</button>

✓ Fixed

<button>Submit form</button>
<!-- or aria-label="Submit form" -->

3. Contrast ratio calculator

Pick a text colour and a background colour. The page computes the WCAG contrast ratio from the relative luminance of each colour and checks it against the two Level AA thresholds.

Try it

Type a hex colour such as #767676 or use the picker.

Large sample text, 24px bold

Normal sample text at 16px, the size that needs 4.5:1.

4.54:1

How it works: each sRGB channel is linearised (c/12.92 when c is at most 0.04045, else ((c+0.055)/1.055)^2.4), then L = 0.2126R + 0.7152G + 0.0722B. The ratio is (L1 + 0.05) / (L2 + 0.05) with the lighter colour as L1. The result is truncated, not rounded, to two decimals, so 4.499 never shows as a pass. The 3:1 line applies to large text (from 18.66px bold or 24px regular) and to UI components such as input borders and icons.
