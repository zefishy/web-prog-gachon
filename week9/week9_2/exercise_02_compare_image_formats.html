Compare image formats

A live <picture> with WebP sources and a JPEG fallback. See which file your browser picks, then confirm it in the Network tab.

Live demo: WebP with a JPEG fallback

The image below is a <picture> with two WebP sources (400 and 800 pixels wide) and a JPEG <img> with the same two sizes. The browser picks the first <source> whose type it understands, then chooses a width from srcset using sizes and the screen density. The readout shows what it actually chose.

The format is read from the file extension in the chosen URL. picsum.photos is a placeholder service that converts on the fly, so the byte sizes are not meant as a benchmark.

The markup

<picture>
  <source type="image/webp"
          srcset="https://picsum.photos/id/1015/400/200.webp 400w,
                  https://picsum.photos/id/1015/800/400.webp 800w"
          sizes="(max-width: 500px) calc(100vw - 80px), 510px">
  <img src="https://picsum.photos/id/1015/800/400.jpg"
       srcset="https://picsum.photos/id/1015/400/200.jpg 400w,
               https://picsum.photos/id/1015/800/400.jpg 800w"
       sizes="(max-width: 500px) calc(100vw - 80px), 510px"
       width="800" height="400"
       alt="A river winding through a green valley between steep mountains"
       fetchpriority="high">
</picture>
  • type="image/webp" lets a browser without WebP skip the source without downloading it.
  • srcset with w descriptors gives the browser the real widths; sizes tells it how wide the image will be, so it can choose before layout.
  • width and height reserve the 2:1 box, so there is no layout shift.
  • fetchpriority="high" is for this image only because it is the first and largest thing on the page.

See the fallback work

This second picture lists a source with a format no browser knows. The browser skips it and uses the JPEG in the <img>, which is exactly what an old browser does with image/webp. It also uses loading="lazy" because it is below the fold. 

<picture>
  <source type="image/x-not-a-real-format"
          srcset="https://picsum.photos/id/1018/800/400.webp">
  <img src="https://picsum.photos/id/1018/800/400.jpg"
       width="800" height="400" loading="lazy"
       alt="Misty mountains above a lake">
</picture>

How to verify it in the Network tab

The readout is the browser reporting on itself. The Network tab is the independent check.

  1. Open this page in Chrome or Edge, then open DevTools with F12 and choose the Network tab.
  2. Tick Disable cache, click the Img filter, and reload with Ctrl+R.
  3. Find the request for 1015/…. The Type column should say webp and the URL should end in .webp. If it says jpeg, your browser skipped the WebP source.
  4. Read the Size column and compare it with the same request for the .jpg version, which you can open in a new tab. Note the numbers yourself; they change with the picture.
  5. Narrow the window below 500 pixels and reload. The request should switch to the 400-wide file.
  6. Open the throttling menu (default No throttling) and pick a slow preset, then reload. The smaller file is the one that arrives sooner.
  7. Scroll to the second picture. Its request should appear only now, because of loading="lazy".
